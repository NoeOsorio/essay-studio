# Data Model: Rubric, Sources and History Panels

Every change is additive. Rust stores `rubrica` and `fuentes` as opaque JSON (`storage.rs:25,29`), so **no Rust model change and no migration**. Old essays load unchanged; absent fields mean "never read".

## Criterio (unchanged)

`id` (generated by the renderer, never by the model), `nombre`, `peso` 1 to 5, `descripcion`.

## Rubrica (one optional field)

| Field | Type | Notes |
|---|---|---|
| `criterios` | `Criterio[]` | Unchanged |
| `consigna?` | `{ texto: string; archivoNombre?: string; agregadoEn: string }` | The pasted or dropped assignment, so the material survives if the AI is unavailable and retry needs no new drop. Never sent in a review. |

`updateRubrica` clears the rubric when `criterios` is empty. It changes to keep the field when `consigna` exists, otherwise a saved assignment is lost when the AI fails.

## Fuente (optional fields)

Existing fields keep their meaning: `id`, `nombre`, `cita` (full APA reference), `contenido`, `origen`, `archivoNombre`, `agregadoEn`.

| Field | Type | Notes |
|---|---|---|
| `autores?` | `{ apellidos: string; nombres?: string }[]` | As printed in the document. Double surnames need the split, so it comes from the model and each part is checked. |
| `anio?` | `string` | Four digits, checked |
| `publicacion?` | `{ revista?, volumen?, numero?, paginas?, editorial?, doi? }` all strings | Each checked |
| `citaRevisadaEn?` | ISO 8601 | Set when extraction applied. Tells "read and something is missing" from "older source, never read". |

**Derived, never stored**: short citation `(Mayer et al., 1995)`, what is missing (autor, año, título, only when `citaRevisadaEn` is set), the reading state.

**Reading state** lives only in the store as `lecturas: Record<sourceId, "leyendo" | "fallo">` plus one rubric entry. Never persisted, so a crash cannot leave a source stuck in "reading".

## Rules for applying an AI result

1. The same essay is still open and the source id still exists; otherwise the result is dropped.
2. Only empty fields are filled.
3. `nombre` counts as empty when it is blank or still equals the filename stem of `archivoNombre`. That stem is a placeholder, not a value he set. A plain note with no citation data keeps its stem, so `toHaveValue("notas-sapolsky")` still holds.
4. `cita` is rebuilt from fields only while it is empty or still equals what the builder produced from the previous fields. Once he edits it, it is his.
5. A rubric proposal applies directly only if the rubric still has no criteria when the result arrives. Otherwise it waits for confirmation. Before a confirmed replacement the current state is saved as a `before-restore` version.

## Ingest normalization (once, then stored)

Applied to PDF text only, before `contenido` is saved, so later evidence offsets stay valid: NFKC (ligatures), remove NUL, CRLF to LF, join `letter-\nletter` when both are lowercase, collapse runs of spaces and tabs. Pages join with a blank line. Line breaks otherwise stay. Pasted text and `.txt`/`.md` stay byte-exact as today.

## Duplicate sources

A new source is a duplicate when its canonical text (NFKC, case fold, whitespace collapsed) equals an existing source's. `import.ts` then offers the existing one instead of adding it.

## Limits (each with its reason next to it)

Wire limits live in `sidecar/src/review-contract.ts`, which owns every one in the series, and `src/lib/materials/limits.ts` imports them. That file keeps only product limits.

| Constant | Value | Lives in, and why |
|---|---|---|
| `MAX_PDF_BYTES` | 50 MiB | Product. Ceiling: the file sits in webview and Rust memory during import. Text-bearing papers are far smaller; beyond this it is nearly always scans. Also enforced in Rust. |
| `PDF_TIMEOUT_MS` | 60,000 | Product. 247 pages took about 1 s. Protects against a hostile or broken file. |
| `MIN_CHARS_PER_PAGE` | 20 non-space, average | Product. Below this a PDF has no usable text (a scan with only page numbers). |
| `MAX_INGEST_CHARS` | 1,000,000 | Product. About 350 pages at the measured 2,900 characters per page. Larger than 006's wire limit `MAX_SOURCE_CHARS` (680,000): a source between the two is saved and can be reviewed as a prefix, but Hazme preguntas shows its «too large» state for it. |
| `MAX_ESSAY_SOURCE_CHARS` | 5,000,000 | Product. Keeps `get_document` with sources under the 16 MiB MCP cap at the 3-byte UTF-8 worst case, and bounds the whole-file autosave. |
| `REVIEW_TEXT_BUDGET` | 400,000 characters, essay plus sources | Wire. At most 1.2 MB of UTF-8, safely under the 2 MiB line cap by construction. About 115k tokens at an assumed 3.5 characters per token, leaving room for instructions and output in a 200k context. The token figure is an estimate, checked in the real cases. |
| `CITATION_PREFIX_CHARS` | 12,000 | Wire. About 4 pages. Metadata is on page one in every real sample; stopping early keeps reference lists out of the year check. |
| `ASSIGNMENT_MAX_CHARS` | 80,000 | Wire. About 27 pages, more than any assignment. Longer text uses its beginning and says so. |
| `EXTRACT_CONCURRENCY` | 2 | Product. Part of the sidecar's cap of 11: review 4, questions 5, extract 2. |

## Which sources go to a review

One pure function, called inside `critique()` so every caller gets it. Sources whose surname and year appear in the essay go first, then newest first. Each is sent whole while it fits. The first that does not fit is sent as a prefix if at least 20,000 characters remain, flagged `recortada: true`, then the fill stops. A prefix keeps evidence offsets valid. Omitted sources are reported to the review surface as one quiet line. If the essay alone exceeds the budget, a clear message appears and no request is sent.

## Costs this format carries (not fixed here)

- Each snapshot embeds all source text. At 3 MB of sources, 20 automatic snapshots are 60 MB plus 3 MB per close, with close snapshots never pruned. At the 5,000,000 cap, 100 MB plus 5 MB per close.
- Autosave rewrites all source text each time.
- `reviewFingerprint` covers all source text. Spec 005 caches each source's part of the hash in a `WeakMap` keyed on the `Fuente` object, so a render or a save re-hashes only sources that changed.

The fix is in the plan's separate proposal.

## Version (unchanged)

Snapshot kinds stay `auto`, `close`, `manual`, `before-restore`. Only `manual` shows «La guardaste tú».
